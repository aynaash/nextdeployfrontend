# Quick Start

Deploy a Next.js app with NextDeploy in a few minutes. Everything lives in one
config file (`nextdeploy.yml`) and one command (`nextdeploy ship`).

## Prerequisites

- ✅ **NextDeploy CLI installed** — see the [Installation Guide](/docs/installation).
- ✅ **A Next.js application** — create one with `npx create-next-app@latest`.
- ✅ **A deployment target** — a VPS (SSH access), AWS, or Cloudflare.

<Info>
NextDeploy is a Go CLI, not an npm package, and its config is YAML
(`nextdeploy.yml`) — not a JavaScript file.
</Info>

## Step 1 — Initialize

From the root of your Next.js project:

<CodeBlock title="Scaffold the config" language="bash">
{`cd my-nextjs-app
nextdeploy init`}
</CodeBlock>

This scaffolds a `nextdeploy.yml` (and a `Dockerfile` if you don't have one).

## Step 2 — Configure your target

Edit `nextdeploy.yml`. Pick the tab for where you want to deploy:

<Tabs defaultValue="vps" className="w-full">
  <TabsList className="grid w-full grid-cols-3">
    <TabsTrigger value="vps">VPS</TabsTrigger>
    <TabsTrigger value="aws">AWS</TabsTrigger>
    <TabsTrigger value="cloudflare">Cloudflare</TabsTrigger>
  </TabsList>

  <TabsContent value="vps" className="space-y-4">
    <h3 className="text-xl font-semibold">VPS (Caddy + nextdeployd over SSH)</h3>

    <CodeBlock title="nextdeploy.yml" language="yaml">
{`version: "1.0"
target_type: vps

app:
  name: my-nextjs-app
  port: 3000
  environment: production
  domain: myapp.com        # Caddy auto-provisions HTTPS

servers:
  - name: prod
    host: 203.0.113.10     # your VPS IP
    port: 22
    username: ubuntu       # an SSH user that can sudo
    key_path: ~/.ssh/id_rsa`}
    </CodeBlock>

    <p>
      A VPS needs to be provisioned once before the first ship. See the full
      <a href="/docs/targets/vps"> VPS Deployment guide</a> for <code>nextdeploy prepare</code>,
      secrets, DNS, and rollbacks.
    </p>
  </TabsContent>

  <TabsContent value="aws" className="space-y-4">
    <h3 className="text-xl font-semibold">AWS (Lambda + S3 + CloudFront)</h3>

    <CodeBlock title="nextdeploy.yml" language="yaml">
{`version: "1.0"
target_type: serverless

app:
  name: my-nextjs-app
  environment: production`}
    </CodeBlock>

    <Info>
      Serverless requires Next.js <code>output: "standalone"</code>. Configure your AWS
      credentials in your environment before shipping.
    </Info>
  </TabsContent>

  <TabsContent value="cloudflare" className="space-y-4">
    <h3 className="text-xl font-semibold">Cloudflare Workers (beta)</h3>

    <CodeBlock title="nextdeploy.yml" language="yaml">
{`version: "1.0"
target_type: cloudflare

app:
  name: my-nextjs-app
  environment: production`}
    </CodeBlock>

    <Info>
      Cloudflare uses the <code>nextcompile</code> adapter to build for Workers + R2 + KV.
    </Info>
  </TabsContent>
</Tabs>

<Info>
See `sample.nextdeploy.yml` in the repo for the complete annotated schema
(secrets, SSL, logging, database, backups, webhooks).
</Info>

## Step 3 — Preview, then ship

Preview what will happen without changing anything, then deploy:

<CodeBlock title="Deploy" language="bash">
{`nextdeploy plan      # show what will happen, change nothing
nextdeploy ship      # build + push + deploy
nextdeploy ship -v   # same, with verbose output`}
</CodeBlock>

`ship` builds your app locally (skipping the build if the Git commit hasn't
changed), packages it, and deploys to your target.

<Success>
🎉 Your Next.js app is deploying. For VPS, point your domain's DNS at the server
(see the `dns.md` file `ship` writes) so HTTPS can be issued.
</Success>

## Step 4 — Verify and operate

<CodeBlock title="Day-to-day commands" language="bash">
{`nextdeploy status              # active release, port, uptime
nextdeploy logs -f             # tail production logs
nextdeploy rollback --steps 1  # revert to the previous release
nextdeploy destroy             # tear the app down`}
</CodeBlock>
